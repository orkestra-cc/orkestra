# Module: LLM — credentials, models, grants and the gateway for language models

_Path: `/backend/internal/core/llm`_
_Parent: [../AGENTS.md](../AGENTS.md)_

[← Core](../AGENTS.md) | [☰ Backend](../../../AGENTS.md) | [Root](../../../../AGENTS.md)

## Purpose

Owns everything an installation needs to let its modules call a language model: the org-scoped **API-key credentials** (secrets sealed in an envelope), the **model catalog** (capabilities, purposes with priority, who pays), the per-user **grants** that decide who may use a model, and `iface.LLMGateway`, the only surface other modules use to call a model ([ADR-0022](../../../../docs/adr/0022-core-llm-module.md)). Tier 1 only: every row belongs to an **internal** organization.

Delivery was in three steps and all three are built: catalog, access resolver, envelope vault, admin and self routes, late KMS/audit wiring, `Resolve` and `ListUsable`; the six provider adapters, the router (budget reservation, breaker, same-kind fallback, ledger finalization, metrics), the usage ledger, monthly rollup and budget, budget alerts through a durable outbox, the reconciler, the retention purge, credential test, model discovery, the admin prompt test, the usage report and budget routes; and **Sign in with ChatGPT** (SIWC): per-user linked ChatGPT accounts that `credentialRef.kind = user_account` models bill to (see «Sign in with ChatGPT»). The PIIProducer covers grants, actor ids, usage rows, budgets, delivered alerts and linked accounts. Two things are not verified live: the code exchange of `hosted_paste` from a remote backend, and the whole plan route against a real ChatGPT account (see «Known limitations»).

### Secret envelope

`{alg: "kms"|"local", keyId, keyVersion, schemaVersion, ciphertext}` (all `json:"-"`). `ciphertext` is base64 of the sealed bytes. The display tail lives only on the document as top-level `secretLast4` (set by `models.Last4`, empty below 8 characters), never inside the envelope. AAD is `tenantId|resourceUuid|field|schemaVersion`; `Seal`/`Open` refuse an empty part or one containing `|` (`ErrInvalidEnvelopeContext`). The algorithm is chosen at write time and `Open` dispatches on the stored `alg`. On the KMS path `iface.ErrKMSCiphertextInvalid` (truncated, tampered, foreign key) becomes `ErrEnvelopeCorrupt`; `iface.ErrKMSKeyDeleted` and infrastructure errors pass through unchanged. On the KMS path `Seal` obtains the key with `CreateKey(tenantID)` and records its ID only in the envelope; the tenant row's `KMSKeyID` may stay empty (an org created before KMS was wired), and `tenant.PurgeTenant` resolves the key the same way so the crypto-shred still covers these secrets.

## Dependencies

- **Modules** (`Dependencies()`): `user`, `tenant`, `notification` (budget alerts).
- **Optional services**: `ServiceNotificationSender` (`iface.NotificationSender`) and `ServiceOperatorUserProvider` (`iface.UserProvider`, for the recipient's address and language) for budget alerts — without either, each alert is a logged no-op and the outbox row is marked sent; `deps.RedisAdapter` for the admin rate limits (absent → unlimited), the Sign in with ChatGPT rate limits (same) and, with different failure semantics, its one-shot state store and refresh lease (see «Sign in with ChatGPT»).
- **Required services**: `ServiceTenantDirectoryReader` (`iface.TenantDirectoryReader`) — `ReplaceGrants` uses `ListTenantMembers` to check that every grantee is a member. Init fails if it is absent.
- **Optional services**: `ServicePIIProducerRegistry` (the producer is registered when present).
- **Provides**: `ServiceLLMGateway` → `*services.Gateway`, which satisfies `iface.LLMGateway`, `iface.KMSProviderSetter` and `iface.AuditSinkSetter`.
- **Late-injected by compliance** (compliance initializes after this module and does not declare a dependency on it): the KMS provider and the audit sink arrive through the two setters. Until they do, audit emission is a no-op and secrets are sealed with the local key if one exists. `cmd/server/core_load_order_test.go` pins `logging → llm → compliance`; do not reorder the catalog.
- **Environment**: `LLM_SECRET_ENCRYPTION_KEY` (64 hex), read with `os.Getenv` in `Init`; `OPERATOR_API_URL` (the operator API's public origin, `cfg.Server.Operator.PublicURL`, derived from `CONSOLE_HOST` when unset) reaches the module through `llm.WithOperatorPublicURL` in `cmd/server/catalog.go` because `module.Dependencies` carries no config. Sign in with ChatGPT needs it (see «Sign in with ChatGPT»); `docker/AGENTS.md` lists the env-var contract.
- Imports no other module's `services/` or `repository/`; everything cross-module goes through `pkg/sdk/iface`.

## Lifecycle

- **Init**: builds the vault from `LLM_SECRET_ENCRYPTION_KEY`. A **missing** key logs a WARN and leaves the vault without a local key; a **malformed** key logs a WARN and is treated as absent. Neither stops the boot (a core `Init` error is fatal, and an unconfigured optional capability must not be). The value is never logged. It then resolves the tenant directory, builds the three repositories, `CatalogService`, `Registry`, `AccessResolver` and `Gateway`, registers the gateway under `ServiceLLMGateway`, registers the PIIProducer, and builds the handlers.
- **`HotReloadConfig()`** is `true`. `allow_hosted` is read through `deps.GetConfigBool` on every catalog decision and every resolver read (one `cfg` accessor shared by `CatalogService` and `AccessResolver`). `siwc_mode` and `siwc_paste_port` are read per call through the same accessors (one exception: the callback route is mounted at boot, see «Sign in with ChatGPT»). The other keys are read per call through `readSettings`, which **clamps** them (`clampSettings`): `request_timeout <= 0` → 60s, `usage_retention_days` 31–3650 (the current month's rows feed the self usage route), `budget_warn_pct` 0–100, `budget_reserve_output_tokens` 1–131072. The reservation TTL is derived, never configured: `2 × request_timeout + 60s` — two full attempts (a fallback) plus finalization, always far above the router's finalization window, so a reservation never expires under a call that may still run.
- **Init** also registers the six adapters (`providers.RegisterAll`) with one SSRF-safe client per provider kind (`clientFor`: `Timeout 0`, default `HeaderTimeout` for non-stream responses, `IdleTimeout 30s` for requests marked `WithStreaming`), builds the ledger/rollup/budget/outbox repositories and `BudgetStore`, the `BudgetService`, the router (`NewOrgCredentialResolver`, breaker 3 faults / 30s, `metrics.Default()`) wired with `Gateway.SetRouter`, the notifier, outbox worker, reconciler and the retention job, and the ops/usage handlers.
- **`Start`/`Stop`** (logging-module pattern, `lifecycleMu`, idempotent): `Start` launches the outbox worker (30s), the reconciler (1 min) and the retention purge (first run after 1 min, then daily: `llm_usage` older than `usage_retention_days`, rollups older than 24 months, `sent`/`failed` outbox rows older than the usage cutoff); each sweep handles every row under the row's own tenant context (rulings 3.5/5.4). `Stop` cancels and waits.
- **`HealthCheck`** returns `nil` unconditionally: a missing key only disables secret writes (already warned once at Init), the rest of the module works.

### Configuration

| Key | Default | Env var |
|---|---|---|
| `allow_hosted` | `false` | `LLM_ALLOW_HOSTED` |
| `request_timeout` | `60s` | `LLM_REQUEST_TIMEOUT` |

| `budget_warn_pct` | `80` (0–100) | `LLM_BUDGET_WARN_PCT` |
| `budget_reserve_output_tokens` | `4096` (1–131072) | `LLM_BUDGET_RESERVE_OUTPUT_TOKENS` |
| `siwc_mode` | `disabled` (`disabled\|loopback_local\|hosted_paste`) | `LLM_SIWC_MODE` |
| `siwc_paste_port` | `14555` (1024–65535, advanced, shown only for `hosted_paste`) | `LLM_SIWC_PASTE_PORT` |

Groups: `providers`, `limits`, `siwc` ([ADR-0012](../../../../docs/adr/0012-module-config-group-contract.md)). `siwc_mode` other than `disabled` requires `allow_hosted`; `config_validation.go` refuses a contradictory snapshot with `llm.siwc_config_invalid` (422) on every mutation surface, judging the **effective** values (an env-supplied mode included, so activating an environment profile cannot bypass it) and reading `allow_hosted` with exactly the runtime predicate of `GetConfigBool` (`"true"`, `"1"` or `"yes"`; `"TRUE"` is false in both, so the validator and the runtime can never disagree). The live config is **not** re-validated anywhere else by the platform, so `Link` and the callback call `ValidateSIWCConfig` themselves (an env-only `LLM_SIWC_MODE` at boot bypasses the snapshot validator).

The self account routes (`/v1/llm/accounts/openai…`) carry no MFA and no step-up (see «RBAC»). Step-up is `RequireStepUp(5 * time.Minute)`. Credential `PATCH` is included on purpose: re-pointing `baseUrl` sends the stored key to another host. Model writes have no step-up. **Every write group carries `RequireMFA()`** (the authz precedent): with `CEDAR_ENFORCE_ACTIONS` unset the role table decides and the Cedar admin-suffix refusal is only logged, so the route gate is what keeps a password-only administrator (one in the MFA enrollment grace period included) out; on the credential and grant groups it sits before the step-up because step-up alone accepts a password reconfirm from an operator with no enrolled factor whose role does not require one. `TestModule_RouteGuards` pins the order.

Error codes (`shared/errcode`, `llm.` prefix) and statuses: `budget_exceeded` 429 (`Retry-After: 3600`), `rate_limited` 429 (`Retry-After` = rest of the window), `plan_quota_exhausted` 429, `credential_rejected` 422 (provider 401/403; mapped before `provider_unavailable`, which it also wraps), `partial_output` 502, `request_canceled` 499 (the caller hung up; quiet, never a logged 5xx), `user_account_required` / `user_account_reauth_required` / `plan_usage_disabled` 409, `siwc_disabled` 404, `siwc_unsupported_deployment` 409, `siwc_config_invalid` 503 on a user flow (422 when it comes from the settings surface), `siwc_callback_invalid` 422, `siwc_state_invalid` 409, `siwc_denied` 409, `siwc_id_token_invalid` 409, `siwc_exchange_failed` 502, `invalid_request` 422, `not_found` 404, `name_in_use` 409, `credential_in_use` 409, `secret_key_missing` 503, `endpoint_not_allowed` 422, `hosted_disabled` 422, `mock_not_allowed` 422, `grant_not_member` 422, plus the gateway's `not_configured` 503 (FeatureNotConfigured pattern), `no_eligible_model` 403, `model_access_denied` 403, `capability_mismatch` 422, `provider_unavailable` 503. A wrong-tier tenant is `403` with no code; an unknown error is a generic `500` whose cause is logged, with no `llm.internal` code. Audit actions: `llm.credential.{created,updated,rotated,deleted}`, `llm.model.{created,updated,deleted}`, `llm.grants.replaced` (metadata `access`, `granted` count), `llm.account.{link_started,link_denied,linked,selected,unlinked}` (metadata: mode, reauth flag, `planUsageGranted`, `force`; never a token, a code or a state). `ErrSIWCStateUnavailable` (Redis cannot hold the one-shot state) has no code: it is the generic `500` with the cause logged.

## RBAC

Three rules, no role name anywhere in the module:

1. Every `/v1/admin/llm/*` route uses `RequireSystemPermission(<key>)` on a `System: true` permission.
2. Mutations use a `.admin` key (Cedar's admin-suffix rule requires an enrolled second factor; a production `developer` never inherits it). Each mutation is gated by the permission of **its own resource** — `llm.credentials.admin`, `llm.models.admin`, `llm.grants.admin`.
3. Reads use `llm.admin.read`, which a `developer` keeps in production.

Only permissions with a route are declared, because the policy-coverage baseline rejects a declared permission with no route: `llm.admin.read`, `llm.credentials.admin`, `llm.models.admin`, `llm.grants.admin`, `llm.usage.read`, `llm.budgets.admin`, `llm.accounts.admin` (System) and `llm.models.self`, `llm.usage.self`, `llm.accounts.self` (org). `llm.usage.read` implies reading the budget, which the usage report embeds. `authz/cedar/policies/llm.cedar` names the seven System actions (`llm.usage.read` with the platform-roles read permit; `llm.budgets.admin` and `llm.accounts.admin` with the mutations permit); the three `self` keys are covered by the `self`-suffix rule. `TestModule_Declarations` pins 7 + 3.

**MFA scope of the account routes.** The forced unlink is a System `.admin` write, so it follows the rule above: `RequireSystemPermission("llm.accounts.admin")`, `RequireMFA()`, `RequireStepUp(5m)`. The self routes (link, complete, select, unlink, list) act only on the caller's own registrations, the same tier as `me/models`, so they require `llm.accounts.self` and nothing more: a user without MFA can link their own ChatGPT account. Amendment 24 ("`RequireMFA` on every llm write group") therefore applies to the System `.admin` groups.

The nav item `/admin/llm` has `MinRole: administrator`; the console additionally gates tabs on `llm.admin.read` and disables mutations without the matching `.admin` key.

## Gateway contract (`pkg/sdk/iface/llm.go`)

`Chat`, `Embed`, `Resolve`, `ListUsable`. Every entry point first requires an internal tenant, except the availability probe: the registered `*Gateway` also implements `iface.LLMAvailabilityProbe.HasLiveModel(ctx, purpose, need)` for checks that run with no user or org in context (a consumer's `HealthCheck`). It lists the orgs with an active model (`Models.TenantsWithActiveModels`, a `//tenantscope:allow system` distinct read wired by `SetActiveModelTenants`; unwired → `ErrLLMNotConfigured`) and asks each, under its own scope, whether a live model serves the purpose with the purpose fallback below (`AccessResolver.HasLive`); grants and linked accounts are ignored, so `true` means "some operator can be routed", not "every user can". `ChatRequest.Caller` is required and `Purpose` defaults to `default`; the request limits are enforced before any resolution (`ValidateChatRequest`/`ValidateEmbedRequest`; `Options.MaxOutputTokens` is bounded to 1–131072 like every other output limit, since it is the call's output reservation). `ChatResult.Usage` / the `Done` event carry the winning attempt's usage; the ledger charges every attempt. Every rule below works on **live** models only: status `active`, `providerGate(cfg(), provider)` passes under the config read on this call (`allow_hosted`, no `mock` when production-like), and for `credentialRef.kind = org` the credential exists in the org and is `active` (`user_account` models carry no org credential, so they are live as soon as they are active and allowed; whether the **caller** can use one is decided per user, see «Sign in with ChatGPT»; an unknown kind is never live). A model that is not live is invisible to `Usable`/`ListUsable`, `Resolve`, `Candidates` and the purpose fallback, as if disabled. `ListUsable` and `Resolve` additionally drop the `user_account` models the caller cannot use right now (`Gateway.planFilter`). The routing rules in `AccessResolver.Candidates`:

1. no live model in the org → `ErrLLMNotConfigured`;
2. the purpose falls back to `default` **only if no live model of the org declares it**; if some model declares it but the caller may not use it or it lacks a needed capability, the result is empty (`ErrLLMNoEligibleModel`);
3. candidates are ordered by the purpose's priority (lower wins), then name;
4. a `ModelUUID` pin must be among the candidates (`ErrLLMModelAccessDenied` otherwise) — pinning never widens access.

## Routing

`Router.run` for one logical `Chat`/`Embed`:

1. **Candidates** from `AccessResolver.Candidates` (live models, purpose, capabilities, pin).
2. **Reservation**: `BudgetService.Reserve` inserts the `pending` ledger row and reserves estimated input + reserved output against the month (see «Budget semantics»). A refusal is a `budget_blocked` row and `ErrLLMBudgetExceeded`, before any provider call. The reservation TTL is `2 × request_timeout + 60s`; the call must end by `TTL − 5s` (the finalization window), so a reservation never expires under a running call, and an attempt that would not fit is not started.
3. **Breaker** per `provider|baseUrl|modelId|credentialUuid` (3 consecutive provider faults → open 30s, then a single half-open probe; `Release` frees a probe that ended without a verdict). Only provider faults count (ruling 5.2): unavailability, provider timeouts, 5xx, rejected credentials, exhausted quota — never a caller cancel, a deadline the caller lowered below `request_timeout`, an invalid request, a capability gap, the budget or the linked account (a plan-route `401`, `ErrSIWCInvalidUser`, included, whether or not it could still be refreshed and retried, and also after output).
4. **Attempt** with the provider adapter under `min(request_timeout, caller deadline)`. A stream's idle timeout (headers + silence between reads) is `max(30s, request_timeout)`, set per call (`Router.streamIdle`, hot-reloaded): an idle cut is a fallbackable provider fault that counts toward the breaker, so a model thinking silently is bounded by the attempt deadline instead.
5. **Fallback** to the next candidate **with the same `credentialKind`** (D12: the payer never changes) unless the failure is final (`fallbackable`): a caller cancel or a deadline (an attempt that ran out its own deadline included), the budget, the linked-account errors, an exhausted quota (and a circuit it opened), an invalid request and partial output are final. An unavailable provider, a rejected credential, an adapter that cannot be built and an open circuit — one opened by timeouts included — move on; a capability gap skips the candidate. At most 8 attempts are ledgered.
6. **Finalization** on `context.WithoutCancel` with a 5s bound: the row's outcome (`ok`, `fallback`, `error`), attempts, real tokens and the model that answered; the rollup releases the reservation and adds the tokens to the payer's counters; thresholds crossed enqueue alerts. Metrics `orkestra_llm_requests_total{provider,outcome}` and `orkestra_llm_tokens_total{provider,direction}`.
7. **Reconciler** closes any `pending` row whose owner died after its TTL, charging the whole reservation (outcome `error`, code `reconciled_timeout`, through `Finalize`; a late router finalize then gets `ErrAlreadyFinalized` and never counts twice).

## Sign in with ChatGPT

Lets a user bill inference to **their own ChatGPT plan**: a model whose `credentialRef.kind` is `user_account` is paid by the caller's selected linked account, never by the org ([ADR-0022](../../../../docs/adr/0022-core-llm-module.md) D3, D10, D13). OpenAI documents the flow as OpenID Connect with PKCE (`auth.openai.com`, scope `openid profile email offline_access resource.invoke chatgpt.tokens.use.direct`, `resource=https://api.openai.com/v1`) and a callback on `127.0.0.1`.

### Modes and `OPERATOR_API_URL`

`siwc_mode` is one of:

| Mode | Redirect URI | Who completes the exchange |
|---|---|---|
| `disabled` (default) | — | nobody; the routes answer `llm.siwc_disabled` (404) |
| `loopback_local` | `http://127.0.0.1:<port>/v1/llm/accounts/openai/callback`, `<port>` from `OPERATOR_API_URL` | the callback route, automatically (browser and API on the same machine) |
| `hosted_paste` | the same path on `siwc_paste_port` (default 14555) | the user pastes the address the browser shows into the console; `POST …/complete` finishes it |

The redirect host is **always** `127.0.0.1`: never `localhost` (the callback refuses any other host with `unsupported_deployment`, and a pasted `localhost` address fails the redirect comparison), never a remote host, and no token is ever transferred between machines. Either mode needs `allow_hosted`. `loopback_local` needs `OPERATOR_API_URL` to be exactly `http://127.0.0.1:<port>` with an **explicit port other than 80** (no userinfo, no path: a browser omits the default port from the `Host` header, so a port-less or `:80` URL could never match the registered redirect); `hosted_paste` needs `siwc_paste_port` in 1024–65535 and, in production-like environments, an `https` `OPERATOR_API_URL`. `ValidateSIWCConfig` enforces all of it and returns a `*SIWCConfigError` naming the offending field.

The `hosted_paste` reading follows the guide's technical contract to the letter, but OpenAI's overview points remotely hosted applications to an interest form: enabling it on a hosted installation is an operator decision (ADR-0022 D13), recorded in the module settings.

### Why the callback route exists only in `loopback_local`, decided at boot

`GET /v1/llm/accounts/openai/callback` is a raw chi handler on the operator root router, **public** (the browser arrives from OpenAI with no session; the attempt carries the identity) and outside the OpenAPI document. Routes are registered once, in `RegisterRoutes`, from the mode read **at that moment**; in any other mode the route does not exist, so a hosted installation never exposes an unauthenticated endpoint. The consequence: switching **to** `loopback_local` at runtime needs a restart. The handler still re-reads the mode on every request, so switching **away** takes effect at once (it answers the closed `disabled` redirect). An invalid configuration still mounts the route (with a WARN) and the handler refuses every callback until it is fixed. Mounting it without a console origin (`OPERATOR_FRONTEND_URL`, else the platform frontend URL) also WARNs: the closed redirect would then be relative and land the browser on the API host.

### Link, complete, callback

1. **Link** (`POST …/link`, 5 per user per 10 min): re-validates the live config (an env-only mode bypasses the snapshot validator), builds the redirect URI, mints `state`, `nonce` and a PKCE verifier, reads or mints the installation host id (`ext_agent_host_id`, `llm_installation`), and stores the attempt in Redis for **ten minutes**, sealed in the vault (the verifier and nonce never sit readable): user UUID, tenant, host id, redirect URI, mode, client id, label, reauth account. A first link uses the documented `dynamic_agent_client` id and `agent_name_hint`; a reauth uses the registration's own issued client id with `id_token_hint` and `login_hint` (the URL then carries the stored ID token: it goes to the caller's browser only, never to a log or an audit event).
2. **State is one-shot.** `Take` increments a marker (`incrCounter`, increment + expiry atomic) and the first caller wins; a replay, an expired, tampered or unknown state is `llm.siwc_state_invalid`. The store fails closed when Redis is unavailable.
3. **Complete** (shared by the paste endpoint and the callback). After `Take` it checks, in order: the host id equals this installation's; for the paste path the session user **and** tenant equal the attempt's (otherwise `state_invalid` and the attempt stays consumed); the mode is still enabled; the arrival redirect URI equals the attempt's byte for byte (mandatory, fail closed; the callback sets it from the request, the paste path from the pasted URL, whose fragment is ignored — localhost, another port or another path fail here, never against the live config); `error=access_denied` is `llm.siwc_denied`; the issued `client_id` of a first link is required, on a reauth it must match. Then the code is **exchanged by this server**, the ID token is verified (`iss`, `aud` = the issued client id, `nonce`, `exp`, RS256 signature against the discovery JWKS, `sub` required), and a refresh token must have been granted. From the exchange on, the work runs on a context detached from the request (30 s bound): the code is spent at OpenAI, so a browser that hangs up must not leave an issued refresh token neither stored nor revoked. On any later failure the fresh refresh token is revoked (best-effort) rather than left behind. The paste endpoint re-validates the live configuration before anything is consumed, as Link and the callback do; the callback stamps the `RealIP` address into the context, so its audit events carry it.
4. **Store.** A first link inserts a registration (selected unless the user already has a selected one); the same issued client id coming back is a **relink** of that row, allowed only for the same OIDC subject (an equal email never merges two registrations). A reauth must match client id, user and subject (`llm.siwc_id_token_invalid` otherwise, the stored row untouched). The unique `(tenantId, userUuid, clientId)` index and the partial `selected` index make concurrent first links safe (the loser re-reads or inserts unselected). A duplicate whose cause cannot be told (the re-read fails, or the same client id lands right after it) is `llm.siwc_exchange_failed`, never `name_in_use`, and the fresh set is revoked. Labels are at most 100 characters (runes, like the schema).
5. **Callback response.** Always a `302` to `{console}/user/security?tab=ai` with `linked=ok` or `error=<state_invalid|denied|token_exchange_failed|id_token_invalid|disabled|unsupported_deployment>` and `Referrer-Policy: no-referrer`, `Cache-Control: no-store`: never a code, a state, a token, an email or a user id. The closed contract lives only in `handlers/siwc.go`. The host header must be `127.0.0.1[:port]` (otherwise `unsupported_deployment`), and the per-IP limit (20 per 10 min, address from `RealIP`) runs **before** the state is taken.

### Account statuses

| Status | Meaning | Enters when | Leaves when |
|---|---|---|---|
| `active` | usable | linked or reauthorized with the plan scope; a refresh keeps the scope | a terminal refresh (`needs_reauth`); a refresh that no longer grants the scope (`plan_disabled`) |
| `plan_disabled` | identity is valid, but `chatgpt.tokens.use.direct` was not granted | linked or refreshed without the plan scope | a reauthorization that grants it (a `plan_disabled` account is not refreshed on the call path) |
| `needs_reauth` | the refresh token is unusable | a terminal refresh error (fenced write below) | a successful reauthorization (new set, `lastError` cleared) |
| `revoked` | reserved in the enum; v1 never writes it (an unlink deletes the row) | — | — |

Only `active` with `planUsageGranted` is usable: `plan_disabled` → `ErrLLMPlanUsageDisabled` (`llm.plan_usage_disabled`), anything else → `ErrLLMUserAccountReauth` (`llm.user_account_reauth_required`); no linked account at all → `ErrLLMUserAccountRequired`. `lastError` holds an `llm.*` code only (`llmCode` rejects anything else), never provider text.

### Token refresh

A token within 60 s of `expiresAt` is refreshed before use. The refresh token rotates, and using one twice is `refresh_token_reused` (a forced reauth), so a refresh must happen once:

- **In-process single-flight** per `(org, account)` (`golang.org/x/sync/singleflight`); the flight runs on a context detached from the first caller's cancellation, 30 s bound, and every flight first re-reads the stored set.
- **Redis lease** across replicas (`llm:siwc:refresh:<account uuid>`, `Incr` + 30 s TTL, deleted on release); a replica that loses it polls the stored set (up to 10 s) for the winner's rotation. Without Redis, or on a Redis error, the lease **fails open** (WARN): the in-process single-flight still applies, and a blocked plan path on a Redis blip would be worse than the rare duplicate refresh.
- **The token set is replaced in one update fenced by compare-and-swap on the previous `savedAt`** (`UserAccounts.ReplaceTokens`; times truncated to the millisecond). A lost swap serves the newer stored set and revokes the one it drops, but only when it is provably not the one now stored (an IdP that echoes the same refresh token must not be revoked).
- An omitted `refresh_token`, `scope` or `id_token` keeps the stored one; `expires_in` 0 means 3600 s; `earliest_refresh_at` (clamped to ≤ 24 h ahead) is waited for when ≤ 5 s away, otherwise a still-valid token is used or the call is unavailable.
- **Terminal codes** (`invalid_grant`, `invalid_refresh_token`, `token_expired`, `refresh_token_expired`, `refresh_token_invalidated`, `refresh_token_reused`) → the account becomes `needs_reauth` through `SetStatusIf`, **fenced on the `savedAt` of the set that failed**, so a stale presenter can never flag a newer, valid set (it gets the newer set instead). A corrupt refresh envelope is terminal too. The sentinel `ErrSIWCRefreshTerminal` never leaves the module: callers see `ErrLLMUserAccountReauth`.
- `invalid_client` is a **configuration** error, not a token error: credentials and status are kept, the call is unavailable and a WARN is logged (a reauth with the same issued client id would fail the same way). The router treats it as final (no fallback to the next `user_account` candidate, which would present the same client) and the breaker does not count it; the same token set is not presented again for one minute (an in-memory, per-registration backoff keyed on `savedAt`, so a reauth or rotation is never held back).
- A rotation whose registration was deleted meanwhile (an unlink or erasure racing the refresh) is revoked too; a token the IdP echoed is left alone (the unlink already revoked it). The other side of that race: unlink and erasure delete first (`Delete` / `DeleteByUser` are `FindOneAndDelete` and return the removed documents) and revoke the refresh token **of the document the delete removed**, never of an earlier read, so a set stored between the read and the delete is revoked too.
- A rotated set the vault (KMS) cannot seal is sealed again, the **same** returned set, up to 3 times (200 ms apart); the provider refresh is never repeated, because the stored refresh token is already spent. If it still fails and the provider rotated the refresh token, the new one is revoked (best-effort) and the registration goes `needs_reauth` through the savedAt-fenced terminal write (`ErrLLMUserAccountReauth`); a response that kept the refresh token loses nothing (the stored set stays, the call is unavailable).
- An inference `401` (`subscription_sharing_invalid_user`) before any output triggers **one** forced refresh and one retry of the same candidate per logical call (`Router`); a terminal refresh there ends in `needs_reauth`.

### The plan path

The `openai` adapter picks `ProfileSIWC` when the credential kind is `user_account`. It talks to the Responses API with the account's access token and is the only adapter that does. **Never sent** on this path: `temperature`, `max_output_tokens` (refused as a capability mismatch), `metadata`, `user`, `previous_response_id`, `system` messages (system text goes in `instructions`; the gateway refuses the `system` role), and no embeddings (the router refuses them before the account is resolved). **Always**: `store: false` and `stream: true`. `response.incomplete` counts as a terminal success (it carries usage) finishing with `length`/`other`. Plan-route failures are classified by `providers.ClassifySIWCHTTP` / `ClassifySIWCCode`: `subscription_sharing_user_not_eligible` and any `403` without a code → plan usage disabled; `…_usage_limit_exceeded` → `llm.plan_quota_exhausted`; `…_usage_unavailable`, `…_user_unavailable` → provider unavailable (fallbackable; in v1 the breaker, 3 failures → 30 s, is the bounded backoff); `…_unsupported_capability` → capability mismatch; `…_route_not_supported`, `chatpass_v2_*` → unavailable, **final**: no fallback to the next `user_account` candidate (same account, same issued client, same grant) and never counted by the breaker (configuration, not a provider fault); `401` / `…_invalid_user` → the forced refresh above. A `401`/`403` on this path is **never** `ErrUnauthorized` (the remedy is the user's account, not the operator rotating an API key), and the linked-account errors never trip the breaker. The plan-route failure logs carry only the account UUID, the `llm.*` code and the allowlisted status, provider code and request id.

### Per-account catalog

What a user may call is the intersection of the grant/access model **and** the selected account's plan catalog (`ListModels` on the plan profile, cached 5 minutes **per account and token set**: an entry is keyed on the account UUID plus the `savedAt` of the set it was read with, so a reader holding another set (a rotation stored on another replica, whose in-process invalidation never reaches this one) misses it, and a read of an older set that ends late never replaces a newer entry; dropped on select, refresh, reauth, unlink and `needs_reauth`; one forced refresh and retry on a `401`, and `PlanModels` then returns the refreshed credential, which the resolver hands to inference instead of the rejected token). `Resolver` answers a `user_account` model only for a model id in that catalog (otherwise `ErrLLMCapabilityMismatch`); `ListUsable`, `me/models` and `Resolve` drop the models the caller cannot use right now, `Chat` keeps the classified errors. Selecting another registration therefore changes "My models". The payer identity for the breaker and the ledger is the account UUID; fallback never leaves the `user_account` kind (D12). A job with no user in its context has no account and answers `ErrLLMUserAccountRequired`.

### Rate limits and secrets

Link 5 per user, complete 10 per user, callback 20 per client IP, all per 10 minutes (`RateLimiter.Check` → `*RateLimitedError`, 429 + `Retry-After`). No ID, access or refresh token, authorization code, code verifier, state or reauth authorize URL reaches a log, an error, an API response or an audit event; the three tokens are separate vault envelopes (`idToken`, `accessToken`, `refreshToken`) in the AAD. The OIDC client reads error bodies bounded and keeps only an identifier-shaped error code.

## Operational

- **Tickers** (`Start`): outbox worker every 30s (lease 2 min, backoff 1 → 64 min, 20 attempts then `failed`), reconciler every minute, retention first after 1 min then daily. All stop with `Stop`.
- **Metrics** (ADR-0002): `orkestra_llm_requests_total{provider,outcome}` (`ok\|fallback\|error\|budget_blocked`) and `orkestra_llm_tokens_total{provider,direction}` (`input\|output`, as ledgered by the router, partial-output charges included; the reconciler's orphan charges are in the ledger and the rollup but not in this metric). `orkestra_llm_siwc_link_total{outcome}` counts link completions (loopback callback or pasted URL): `linked`, `plan_disabled` (linked without plan usage), `denied`, `state_invalid`, `id_token_invalid`, `exchange_failed`; anything else collapses to `unknown`. Labels are collapsed to closed sets.
- **Notification templates**: `llm.budget_warning`, `llm.budget_exhausted`, `llm.budget_oversized` (en/it, category `llm.budget`, transactional). With the notification module in `noop` the rendered alert is logged on the backend.
- **Admin ops limits**: credential test and model discovery 10/min per org + credential, prompt test 10/min per org + user (`llm.rate_limited`, `Retry-After`).

## Budget semantics

- **Admission, not a kill switch.** A call reserves estimated input + reserved output in one transaction that admits it only if `consumed + reserved + requested <= limit`; real usage can exceed the reservation (a long answer). Under `warn_only` it is admitted anyway; an unknown action blocks (fail closed).
- **Exhausted alert (ruling 4.1, refined by the final review).** Under `block` consumption never reaches 100%, so the `exhausted` alert fires on the **first refused reservation** of the period that finds `consumed + reserved` already at the warn threshold (`warnPct` of the limit, the limit itself when `warnPct` is 0; `models.RefusalAlerts`) — `budget_blocked` row + `exhaustedAt` mark + outbox row in the refusal's transaction — or when finalized consumption reaches the limit. A refusal of one oversized request against a largely unused balance is ledgered `budget_blocked` but does not mark `exhaustedAt`, so it cannot burn the month's only exhausted alert. When that refused request alone needs more than the whole limit (`models.RefusalOversized`: no balance could ever admit it), the refusal instead marks `oversizedAt` and enqueues the period's single `oversized` event (payload adds `requestTokens`; template `llm.budget_oversized`), so a budget smaller than one call does not block the org silently; a request under the limit refused against an unused balance still sends nothing. Each alert is one per org and period (the rollup mark, backed by the unique `(tenantId, period, threshold)` outbox index). The email says a call was refused (block) or that calls continue (warn_only).
- **Partial output (ruling 5.5).** An attempt that already streamed output to the caller and then failed is never retried on another model (`llm.partial_output`) and is charged conservatively (spec amendment 6): with usage reported by the provider, the reported input (the estimated input if missing) and the larger of the reported output and the emitted bytes / 3; without reported usage, the estimated input and the larger of the reserved output and the emitted bytes / 3. An orphan the reconciler closes is charged its whole reservation. A sink that refuses only the final `Done` event does not make the call partial: the provider completed, so it is ledgered `ok` with its reported usage and the sink's error is returned to the caller.
- **Per-org serialization.** Every reservation and every finalization of one org writes the same monthly rollup document inside a transaction, so concurrent calls of one org serialize through write-conflict retries (the driver retries for up to 120s). Correct by design, but it bounds one org's call throughput to what one document's transactions sustain; orgs do not contend with each other.
- **Alerts.** Recipients: members with `IsOwner`, role `org_owner` or `org_admin` (notification targeting, not authorization — ruling 4.12), plus `notifyExtraUserUuids` still in the org. One `SendTemplated` per recipient (`Type transactional`, `Category llm.budget`, locale from the user's language), each with its own 15s timeout so one slow mail server costs only its recipient. **Progress is per recipient**: each delivery is recorded on the outbox row (`deliveredTo`, `$addToSet` fenced by the worker's lease) and a retry sends only to the recipients still missing, however late it runs. The idempotency key is attempt-scoped, `llm-budget-<eventUuid>-<recipientUuid>-<attempts>`: the notification module replays a key's cached result for an hour, failures included, so reusing one key across retries would replay the failure instead of sending; within one attempt (a worker that crashed between a send and recording it, re-leased without an attempt increment) the same key replays the delivery instead of duplicating it. A delivery whose record fails may be sent twice (at-least-once). The admin prompt-test path that skips grants is not on the registered `Gateway`: `services.NewPinnedRunner(gateway)` hands it to `AdminOps` only.

## Invariants

- **Secrets never leak.** The API key is write-only; it appears in no response, log line, error message or audit metadata (audit metadata also never carries `baseUrl`). `Open` happens just-in-time via `CatalogService.OpenCredentialSecret`; the plaintext is not retained past the provider call.
- **The envelope is context-bound.** Always `Seal`/`Open` with the same `(tenantID, resourceUUID, "secret")`; the tenant must be the stored `TenantID`, not whatever is in a test fake's context.
- **Managing ≠ using.** Access is a grant or `access = everyone`; a model manager has no implicit use. Do not add a role-based shortcut.
- **Access changes only on the grants route.** `access` is not in `LLMModelBody`, `LLMModelPatchBody` or `ModelInput`; `CreateModel` always stores `granted`; `ReplaceGrants(ctx, model, access, userUUIDs)` validates access and membership first (a refusal writes nothing, access included), then sets both in **one Mongo transaction** (`Grants.Replace(ctx, model, access, actor, users)`): it first writes the model document — `$set {access, updatedAt}` + `$inc {grantsRevision: 1}` — then deletes and inserts the grant rows. Because every replacement of a model writes that same document, concurrent replacements write-conflict and `WithTransaction` retries the loser after the winner commits: the end state is always exactly one request (its access and its list), never a union, and a failure writes nothing. Access is always written, never skipped on a value read before the transaction. `Grants.Replace` is the only writer of `access`; `Models.Update` (used by `PatchModel`) is a targeted `$set` of every editable field **except** `access` and `grantsRevision`, so a patch and a grants change cannot revert each other. A replica set is required (as everywhere in Orkestra). With `access = everyone` the grants are kept but dormant and apply again when access returns to `granted`. `TestModelBodiesCarryNoAccess` pins the bodies.
- **Credential writes are field-owned.** `Credentials.Patch` (used by `PatchCredential`) is a targeted `$set` of only the fields the request provided (`name`, `baseUrl` — `$unset` when the provided value is empty —, `status`) plus `updatedAt`, so a rename built on a stale read cannot revert a concurrent disable or endpoint change; both `Patch` and `SetSecret` return the `updatedAt` they wrote, which the service reports back; `Credentials.SetSecret` (used by `RotateCredential`) is the only writer of `secret` and `secretLast4` (and clears `lastTest*`); `Credentials.SetTestResult` is the only writer of `lastTest*` (no `updatedAt` bump) and writes only while the stored ciphertext and base URL are the ones tested. Neither ever writes `createdBy`, `createdAt`, `tenantId` or `uuid`, so a rename racing a rotation keeps the new secret, a stale rotation cannot undo a disable, and no write restores a creator the DSR pipeline pseudonymized. Do not go back to `ReplaceOne` of a loaded document.
- **`user_account` models** must use `openai`, cannot offer embeddings and cannot set temperature or max tokens; the catalog validates this on create and on edit.
- **Fallback never changes the payer** (ADR-0022 D12).
- **Hosted/mock gates apply on create, edit and re-enable** of credentials and models, and on every read through the resolver; disabling is always allowed.
- **A live model needs an active credential.** `CreateModel` and a `PatchModel` that leaves the model active refuse a disabled org credential (`llm.invalid_request`, sentinel `ErrCredentialDisabled`); a model that ends up disabled may keep pointing at one.
- **Model defaults are bounded like request options:** `defaults.temperature` 0–2 (NaN refused), `defaults.maxOutputTokens` 1–`models.MaxOutputTokens` (131072, the `budget_reserve_output_tokens` maximum). The per-model override `budgetReserveOutputTokens` is stored as 1–131072 or absent: on create, absent or `0` means no override; on `PATCH`, absent keeps the stored value and `0` clears it (back to the module default) — a pointer field cannot tell absent from `null`, so `0` is the clear value and both schemas accept `minimum: 0` (`models.budgetOverride`).
- **Endpoints**: fixed vendor URLs for `openai`/`anthropic`/`gemini`; `ollama`/`openai_compatible` need a `baseUrl`; `mock` takes none. In production-like environments only public HTTPS is accepted. The string check is the first line only — `providers.NewHTTPClient` re-validates every resolved address at dial time with `netguard.IsPublicIP`; adapters must build their SDK clients through `providers.OpenAIClientOptions` / `AnthropicClientOptions` / `GeminiClientConfig`.
- **Tool-call signatures**: `iface.ChatToolCall.Signature` is opaque provider state (Gemini 3 thought signatures, base64, ≤64 KiB) that the producing adapter sets on output and echoes on replay; never parse, log or show it, and other adapters ignore it. An unsigned first call of a replayed step in the current turn gets Google's documented bypass value (unverified against the live API).
- **Data-subject rights.** Export uses explicit projections (never a raw model): grants held and issued, credentials and models created (references only), usage rows (counters, codes, model, purpose, caller, attempts, dates — never a prompt, `credentialUuid` or reservation fields), budgets naming the subject (as extra recipient or `updatedBy`) and the alerts delivered to them. Erasure deletes the grants the subject holds; rewrites `createdBy`/`grantedBy`/budget `updatedBy` to the fixed constant `models.ErasedActor` (`erased-subject`), not derived from the user; removes the subject from `notifyExtraUserUuids` and `deliveredTo`. Usage rows: `EraseHardDelete` deletes the finalized ones; `EraseAnonymize` keeps them with `userUuid` replaced and `credentialUuid` removed; pending rows (their reservation is still in the rollup) are anonymized in both modes and left to retention; `Usage.Finalize` never restores `credentialUuid` on a row whose `userUuid` carries the `erased-` prefix (pipeline update with `$cond`), so a call in flight during the erasure stays unlinked. An empty subject is refused (`ErrEmptySubject`) before any query, in export and purge. Credentials, models, budgets and grants issued to others are org assets and stay. **Linked accounts go in both erase modes**: every registration of the subject is deleted, one `FindOneAndDelete` per row, and the refresh token of each deleted document is revoked at the provider (best-effort, `AccountsService.RevokeRegistration` under the row's own org, because the DSR context carries no tenant; rows deleted before a failure are revoked too), so no usable token outlives the request, including one a refresh rotated just before the erasure. Export lists `{uuid, label, email, status, linkedAt, lastUsedAt}` and never a token, the issued client id or the OIDC subject; both repository methods refuse an empty subject (`ErrEmptySubject`), which the producer treats as a refusal, not as zero rows.
- **Usage anonymization is per row (ruling 5.8).** Each kept row gets its own `erased-<random uuid>`, never one pseudonym per subject: a per-subject value would keep the rows linkable into a behavioural profile (times, models, callers, purposes) that, in a small org and joined with other records, can single the person out. Per row, each is one isolated event with counters; the residual risk (matching one row's timestamp against an external log) reveals one call's token counts and ends with retention. The cost is that anonymized rows appear as separate keys in the by-user report. Do not switch to a per-subject value without a new documented assessment in the spec.
- **Huma schema names are package-less**, and Huma panics on duplicates. Every HTTP-visible type here carries the `LLM` prefix (`LLMCredentialView`, `LLMModelBody`, `LLMGrant`, …) because `auth` already owns `CredentialView`. Methods on `Credential` and `Model` have pointer receivers for the same family of reasons (Huma's schema-link transformer cannot rebuild a struct embedding a type with a value method set).
- **Capabilities are persisted through `models.LLMModelCapabilities`** (explicit `bson` tags), not `iface.LLMCapabilities` (json-only, it would be stored lower-cased).
- **No cross-module imports.** Tenant membership comes through `iface.TenantDirectoryReader`; compliance reaches this module only through the registered service and its two setter interfaces.

## Known limitations

- Granting from the console, and choosing extra budget recipients, also need `system.tenants.admin`, because both member pickers use the tenant API; a member endpoint scoped to `llm` is a candidate for a later step.
- The usage report grouped by user shows user UUIDs, not names (and anonymized rows as `erased-…` keys).
- The admin rate limits need Redis; without `deps.RedisAdapter` (or during a Redis outage) they allow every call (fail open, as auth does).
- **Sign in with ChatGPT — not verified live.** Every check against a real ChatGPT Plus/Pro account is pending (plan-route prompt and usage, budget on plan tokens, two accounts, revocation, and above all whether OpenAI accepts a code exchange that starts from a remote backend, which `hosted_paste` depends on). The module ships with `siwc_mode = disabled`; enabling `hosted_paste` on an installation is an operator decision taken after that verification, and it stays disabled on any installation until then.
- **Redis down.** The SIWC state store fails closed (a state that cannot be consumed exactly once is not honored): linking in the paste flow answers a generic `500`, and the loopback callback redirects with `token_exchange_failed`. Only the refresh lease fails open (fenced, see «Token refresh»); the three SIWC rate limits fail open like the admin ones.
- **Consent phishing on the loopback callback (accepted for v1).** The callback is unauthenticated: a user could mint an authorize URL and persuade a victim sitting on the **installation's own host** to approve it, landing the victim's ChatGPT account on the minting user. Mitigations: `loopback_local` only works for a browser on the machine that runs the API (`127.0.0.1`), OpenAI shows a consent screen naming the app, attempts expire in ten minutes and are one-shot; `hosted_paste` is bound to the authenticated session. A browser-cookie binding would close it and is not built.
- **`loopback_local` outside development and the host mux.** Outside `ENV=development` an unmatched `Host` header is answered `421 Misdirected Request` before any route runs. The browser's callback arrives with `Host: 127.0.0.1:<port>`, so on a production-like installation `loopback_local` works only when the operator host (`CONSOLE_HOST`) is that same `127.0.0.1:<port>`; otherwise the callback never reaches the route (the paste flow is unaffected). The module cannot see `CONSOLE_HOST` and does not validate it.
- **Pending live check: the loopback callback reaches the operator API.** No unit test covers the host mux path: a request with `Host: 127.0.0.1:<port>` must reach the operator router (no `421`) on the installation where `loopback_local` is enabled. To be verified with the in-development click-through.
- **A rate-limited callback reads as `state_invalid`.** The redirect set is closed, so the per-IP limit answers `error=state_invalid` even though the attempt was not consumed and can be retried after the window.
- **Plan models are hidden during a provider outage.** The listing intersects `user_account` models with the account's plan catalog; when the catalog cannot be read (provider down, no usable account) they disappear from `ListUsable`/`me/models`/`Resolve`, while `Chat` keeps the classified per-call errors. The two may disagree for that window.
- A failed `user_account` call leaves `credentialUuid` empty on its ledger row (the PR 2 behaviour for failed attempts); a successful one records the account UUID.

The budget tests (`repository/budget_txn_test.go`, `services/budget_mongo_test.go`) exercise real multi-document transactions: they need `MONGO_TEST_URI` pointing at a replica set and skip without it, so a green run without the variable proves nothing about admission or finalization.
