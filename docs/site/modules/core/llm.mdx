# llm

Language-model access for the platform: **credentials**, a **model catalog**, per-user **grants**, and the `iface.LLMGateway` that other modules consume. Added to the always-loaded core by [ADR-0022](/adrs/core-llm-module) — whose API key is used, which models exist, who may use them and how much they may spend are questions every product rebuilds, so the base answers them once. Tier-1 only: every row belongs to an internal organization.

The module boots with zero credentials and zero models. It is healthy in that state and the gateway answers `ErrLLMNotConfigured` until an active model exists, in the same spirit as `notification` booting in `noop`.

## What it owns

Seven collections, all scoped to an internal organization (`tenantId`):

| Collection | Holds |
|---|---|
| `llm_credentials` | An API key per provider: `name`, `provider`, `baseUrl`, the sealed `secret` envelope, the display-only `secretLast4`, `status`, and who created it. Names are unique per organization. |
| `llm_models` | A configured model: provider and model ID, the **capabilities** it offers (chat, streaming, tools, structured output, embeddings and dimensions), a `credentialRef`, defaults (temperature, output limit, effort), the **purposes** it serves with a priority each, `access` (`granted` or `everyone`, set only through the grants route) and `status`. Names are unique per organization. |
| `llm_grants` | One row per `(model, user)` pair that may use a model, with who granted it. |
| `llm_usage` | The per-call ledger: who called (user, calling module, purpose), which model and provider answered, who paid (`org` or `user_account`), token counters, latency, outcome (`pending`, `ok`, `fallback`, `error`, `budget_blocked`), an error code and up to eight attempts (counters only). Never a prompt or an output. Kept `usage_retention_days`. |
| `llm_usage_monthly` | One rollup per organization and UTC month: requests, input and output tokens per payer, tokens reserved by calls in flight, and when the warning and exhausted thresholds were crossed. Kept 24 months. |
| `llm_budgets` | At most one per organization: monthly token limit, warning percentage, action (`block` or `warn_only`), extra alert recipients. No document means no limit. |
| `llm_budget_outbox` | Budget alerts waiting for or after delivery, one per organization, month and threshold, with the recipients already delivered. |

### Secrets and the envelope

An API key is **write-only**: it is accepted on create and rotate and never returned. Reads show `hasSecret` and the last four characters (`secretLast4`, and only when the key is at least eight characters long).

The stored form is an envelope `{alg, keyId, keyVersion, schemaVersion, ciphertext}`:

- `alg: kms` — sealed with the per-tenant key of the compliance module's KMS provider, once compliance has injected one. A tenant purge crypto-shreds the credentials with it, including when the organization predates KMS and its key was first created for an LLM credential.
- `alg: local` — AES-256-GCM with the dedicated `LLM_SECRET_ENCRYPTION_KEY` (32 bytes, 64 hex characters).

The associated data is `tenantId|resourceUuid|field|schemaVersion`, so an envelope copied to another tenant, record or field fails to open; an empty part or one containing `|` is refused on seal and open. On the KMS path a ciphertext the provider cannot open (truncated, tampered with, or sealed under another key) is a corrupt envelope, while a crypto-shredded key keeps its own error. The key is decrypted only when a provider request is built, and never reaches a log, a response or an error message.

:::note Missing key
A missing or malformed `LLM_SECRET_ENCRYPTION_KEY` does not stop the boot. The module logs a warning and treats the key as absent: everything works except saving a secret, which answers `llm.secret_key_missing` (503) until a key or a KMS provider exists. In staging and production the environment checker refuses a missing, placeholder or non-64-hex value before the stack starts.
:::

## Routes

Operator host. Every route requires an authenticated internal-organization context (a tenant of another kind is refused with `403`) and the permission shown. Every write route needs a second factor completed in the session (*second factor*); routes marked *step-up* additionally need it to be fresh, within 5 minutes.

| POST | `/v1/admin/llm/credentials/{uuid}/rotate` | `llm.credentials.admin` | Second factor + step-up. Replaces the API key |

| GET | `/v1/llm/me/usage` | `llm.usage.self` | The calling user's consumption this month, split by who paid |

Collections are returned as `{ "items": [...] }`. Errors carry a stable `llm.*` code:

| Code | HTTP | When |
|---|---|---|
| `llm.invalid_request` | 422 | A field is out of range or malformed (name, provider, base URL, model ID, purposes, capabilities, default temperature 0–2, default output limit 1–131072, …), or a model would be created or left active on a disabled credential |
| `llm.not_found` | 404 | No such credential, model or grant in this organization |
| `llm.name_in_use` | 409 | Another credential or model already has this name |
| `llm.credential_in_use` | 409 | Delete refused: an active model references the credential |
| `llm.secret_key_missing` | 503 | Neither a KMS provider nor a valid local key exists |
| `llm.endpoint_not_allowed` | 422 | `baseUrl` rejected by the SSRF validation |
| `llm.hosted_disabled` | 422 | A hosted provider was requested while `allow_hosted` is off |
| `llm.mock_not_allowed` | 422 | The `mock` provider in a production-like environment |
| `llm.grant_not_member` | 422 | A grantee is not a member of the organization; nothing is written |
| `llm.rate_limited` | 429 | More than 10 credential tests, model discoveries or prompt tests a minute (per organization and credential, or per organization and user for prompts); `Retry-After` gives the rest of the window |
| `llm.credential_rejected` | 422 | The provider refused the key (401/403): wrong, revoked or under-privileged |
| `llm.request_canceled` | 499 | The caller closed the connection while a provider call was running; never counted as a server error |

The gateway adds `llm.not_configured` (503), `llm.no_eligible_model` (403), `llm.model_access_denied` (403), `llm.capability_mismatch` (422), `llm.provider_unavailable` (503), `llm.budget_exceeded` (429, `Retry-After: 3600`), `llm.plan_quota_exhausted` (429) and `llm.partial_output` (502); see [Gateway contract](#gateway-contract) and [Routing](#routing).

## Permissions

All admin permissions are `System: true` — only the platform system roles inherit them, and no role name appears in the module. The suffix carries the rule:

| Permission | Kind | Grants |
|---|---|---|
| `llm.admin.read` | read | See credentials (redacted), models and grants. A `developer` keeps this in production |
| `llm.credentials.admin` | mutation | Create, rotate, re-point and delete credentials |
| `llm.models.admin` | mutation | Create, update and delete models |
| `llm.grants.admin` | mutation | Decide who may use each model |
| `llm.usage.read` | read | See the usage report — which also carries the budget, so this permission reads the budget too |
| `llm.budgets.admin` | mutation | Set the monthly budget, its action and extra recipients |
| `llm.models.self` | self | List the models you may use (an organization permission, not a system one) |
| `llm.usage.self` | self | See your own consumption this month (an organization permission) |

Every `.admin` mutation requires a second factor completed in the session — the route itself checks it, independently of whether the policy engine's admin-suffix rule is enforced — and credential, grant and budget changes additionally require a fresh one (step-up, five minutes; a password reconfirm does not count). A `developer` is not granted an `.admin` key in production. Each mutation emits an audit event (`llm.credential.created|updated|rotated|deleted`, `llm.model.created|updated|deleted`, `llm.grants.replaced`, `llm.budget.updated`, `llm.credential.tested`, `llm.credential.models_discovered`) once the compliance module has injected the audit sink; the event carries names and counts, never secrets or base URLs.

## Configuration

Settings at `/admin/modules/llm`, in two groups. The module hot-reloads its configuration, so a change applies to the next call without a restart; out-of-range values are clamped.

| Key | Default | Env var | Meaning |
|---|---|---|---|
| `allow_hosted` | `false` | `LLM_ALLOW_HOSTED` | Explicit privacy opt-in for hosted providers (`openai`, `anthropic`, `gemini`, `openai_compatible`): prompts and outputs leave the installation. Without it only `ollama` and `mock` can be created, enabled or edited, and existing hosted models stop being offered at once. Disabling a credential or model is always possible |
| `request_timeout` | `60s` | `LLM_REQUEST_TIMEOUT` | Deadline per provider attempt; a consumer may only lower it. A reservation lasts `2 × request_timeout + 60s` |
| `usage_retention_days` | `90` | `LLM_USAGE_RETENTION_DAYS` | Retention of per-call usage rows (31–3650: the current month always stays complete for self usage) |
| `budget_warn_pct` | `80` | `LLM_BUDGET_WARN_PCT` | Default warning threshold for new budgets (0–100) |
| `budget_reserve_output_tokens` | `4096` | `LLM_BUDGET_RESERVE_OUTPUT_TOKENS` | Output tokens reserved against the budget when a model declares none (1–131072). A model's own `budgetReserveOutputTokens` overrides it; sending `0` on create or `PATCH` means no override, so `PATCH` with `0` returns the model to this default |

`allow_hosted` is a technical control. Before enabling it, document the data flow (categories of prompts and outputs, purpose and legal basis, processor, retention, region and transfer mechanism) in your records of processing.

Endpoint rules: `openai`, `anthropic` and `gemini` have a fixed endpoint and take no `baseUrl`; `ollama` and `openai_compatible` require one; `mock` takes none. In a production-like environment a `baseUrl` must be public HTTPS — loopback, private, link-local, CGNAT, multicast, ULA and other special-use ranges, `.local` and `.internal` names and the metadata host are refused.

## Access model

**Managing is not using.** Holding `llm.models.admin` lets you define a model; it does not let you call it. A user may use a model when:

1. the model is **live**: `active`, its provider is allowed by the configuration read on that call (`allow_hosted` for hosted providers, never `mock` in a production-like environment), and the organization credential it rides on exists and is active; **and**
2. its `access` is `everyone`, **or** the user holds a grant for it.

A model that is not live is invisible to the self list, to `Resolve` and to routing, exactly as if it were disabled: turning `allow_hosted` off, or disabling a credential, takes effect at once for every existing model. An organization whose only active models are not live is *not configured* (`llm.not_configured`).

Who may use a model is decided only on the grants route (`PUT …/grants`, `llm.grants.admin` plus step-up), never by `llm.models.admin`: opening a model to everyone is the widest access change, so it has the strongest gate. The route sets `access` and replaces the complete grant list together, in one database transaction: two administrators saving at the same time end with exactly one of their two requests, never a mix, and a failed save changes nothing. Every listed user must be a member of the organization, or the whole call is rejected and nothing (not even `access`) changes. With `access: everyone` the listed grants are still stored but dormant; they apply again when `access` returns to `granted`. `GET /v1/llm/me/models` and the gateway use the same resolver, so the self list shows exactly what a call may route to.

Routing for a purpose: the candidates are the usable models that declare the purpose and offer the capabilities the request needs, ordered by that purpose's priority (lower wins) then name. The purpose falls back to `default` **only** when no live model of the organization declares it at all; if some model declares it but the caller may not use it, the result is empty (`ErrLLMNoEligibleModel`) rather than a silent move to another purpose. A caller may pin one model; a pin must be among its candidates, so pinning never widens access.

A model billed to the user's own linked account (`credentialRef.kind = user_account`) must use the `openai` provider, cannot offer embeddings and cannot set a temperature or output limit.

## Gateway contract

Addons resolve the gateway from the service registry and ask for a *purpose*; they never see a credential:

```go
gw, ok := module.GetTyped[iface.LLMGateway](deps.Services, module.ServiceLLMGateway)
if !ok {
    return errors.New("llm module not loaded")
}

res, err := gw.Chat(ctx, iface.ChatRequest{
    Purpose:  "summarize", // "" means "default"
    Caller:   "myaddon",   // required: the calling module's name
    Messages: []iface.ChatMessage{{Role: "user", Content: text}},
}, func(ev iface.ChatEvent) error {
    // stream deltas; return an error to abort
    return nil
})
switch {
case errors.Is(err, iface.ErrLLMNotConfigured):     // no active model in this organization
case errors.Is(err, iface.ErrLLMNoEligibleModel):   // models exist, none this caller may use
case errors.Is(err, iface.ErrLLMProviderUnavailable):
}
```

The interface has four methods: `Chat`, `Embed`, `Resolve` (the model `Chat` would pick, without calling it) and `ListUsable`. Message roles are `developer`, `user`, `assistant` and `tool`; system text goes in `ChatRequest.Instructions`. Errors are classified with the `ErrLLM*` sentinels in `pkg/sdk/iface/llm.go`, which a consumer maps to its own error codes. The acting user comes from the request context, and the gateway refuses a tenant that is not internal.

`Options.MaxOutputTokens` must be between 1 and 131072, like every other output limit: it is what the call reserves against the budget. `ChatResult.Usage` and the final `Done` event report the usage of the attempt that answered; after a fallback the ledger and the budget also charge the failed attempts.

The compliance module resolves the same service to inject its KMS provider and audit sink (`iface.KMSProviderSetter`, `iface.AuditSinkSetter`).

## Routing

One `Chat` or `Embed` call goes through these steps:

1. **Candidates** — the usable models for the purpose, as described above.
2. **Reservation** — the estimated input plus the reserved output tokens are reserved against the month's budget and a `pending` ledger row is written, in one transaction. A call that does not fit under `block` is refused here (`llm.budget_exceeded`), before any provider is contacted.
3. **Circuit breaker** — per provider, endpoint, model and credential: three consecutive provider faults open the circuit for 30 seconds, then a single probe call is let through. Only the provider's own faults count (unavailability, provider timeouts, 5xx, a rejected key, an exhausted quota); a caller that hangs up or shortens the deadline, an invalid request, the budget or a capability gap never trips it.
4. **Attempt** — the provider call, bounded by `request_timeout` or the caller's shorter deadline. A streamed answer may stay silent for up to `request_timeout` (at least 30 seconds) before it is cut, so a model that reasons before its first output is bounded by the deadline, not by a shorter idle timer.
5. **Fallback** — on a provider failure the next candidate is tried, but only one billed the same way (`org` or `user_account`): a fallback never changes who pays. Cancellation, deadlines, budget and linked-account errors, an exhausted quota, an invalid request and a failure after output already reached the caller (`llm.partial_output`) are final.
6. **Finalization** — the ledger row records the outcome, the attempts and the real tokens; the month's rollup releases the reservation and adds the tokens to the payer's counters. If the process dies before this, a background reconciler closes the row once its reservation expires, charging the whole reservation.

A call that fails after streaming part of its answer is charged conservatively. When the provider reported usage, the charge is the reported input (the estimate if it is missing) and the larger of the reported output and the emitted text (bytes / 3). Without reported usage, it is the estimated input and the larger of the reserved output and the emitted text. A call whose only failure is the consumer's sink refusing the final `Done` event is a completed call: it is charged its reported usage, and `Chat` returns the sink's error.

## Providers

| Provider | Endpoint | Notes |
|---|---|---|
| `openai` | fixed (Responses API) | Official SDK. Chat, streaming, tools, structured output, embeddings |
| `anthropic` | fixed (Messages API) | Official SDK. No embeddings |
| `gemini` | fixed (Gemini Developer API) | Official SDK. Tool calls carry an opaque `Signature` (Gemini 3 thought signatures) that must be sent back on the next turn |
| `ollama` | `baseUrl` required | Native API. The key is optional (sent as a Bearer token for proxied deployments) |
| `openai_compatible` | `baseUrl` required | Chat Completions wire format for self-hosted servers (vLLM, llama.cpp, LiteLLM, …); the key is optional |
| `mock` | none | Deterministic echo for tests and non-production stacks; never selectable in a production-like environment |

Every provider connection re-checks each resolved address at dial time (no private or special-use address in production-like environments), follows no redirect and no proxy, caps response sizes (8 MiB, 32 MiB for embedding calls; OpenAI embeddings are requested base64-encoded), disables SDK retries and never surfaces provider error text: failures become `llm.*` codes. `allow_hosted` gates the hosted providers on the live path and on the admin test, discovery and prompt operations alike.

## Budget

A budget is an **admission control**, not a kill switch. Each call reserves its estimated tokens before it runs; under `block` a call that does not fit the remaining balance (`consumed + reserved + requested > limit`) is refused, under `warn_only` it runs and only alerts. The limit counts input and output tokens of both payers. Real usage can exceed the reservation (a long answer), so consumption can end slightly above the limit.

Alerts go by email to the organization's owners and admins plus the extra recipients still in the organization:

- **warning** when consumption crosses `warnPct` of the limit (the default comes from `budget_warn_pct`; `0` disables it);
- **exhausted** at the first call of the month refused under `block` once consumed plus reserved tokens already reach the warning threshold (or the limit, when `warnPct` is `0`), or when consumption reaches the limit. A single oversized request refused while most of the balance is unused is recorded as `budget_blocked` but sends no alert, so it cannot use up the month's only exhausted alert.

Each alert is sent at most once per organization and month. It is written in the same transaction that crosses the threshold and delivered from a durable outbox with retries; delivery is tracked per recipient, so a retry only reaches the recipients still missing. Delivery is at-least-once: a recipient may rarely receive a copy twice, never zero copies while the notification module works. Templates: `llm.budget_warning` and `llm.budget_exhausted` (English and Italian).

## Usage

`GET /v1/admin/llm/usage` groups the finalized calls of a period by model, user or calling module (requests, input and output tokens), and returns the current month's rollup and the budget. `GET /v1/llm/me/usage` gives a user their own month, split by whether the organization or their own linked account paid. The console's **Usage** and **Budget** tabs at `/admin/llm` read these routes.

## Data-subject rights

The module registers an `iface.PIIProducer` with the subject `llm`. Export returns explicit projections only — never a credential, an endpoint or an envelope: the grants the user holds, the grants they issued, references to the credentials and models they created, their usage rows (model, purpose, calling module, counters, outcome, dates — the ledger holds no prompts), the budgets that name them as extra recipient or last editor, and the budget alerts delivered to them.

Erasure deletes the grants the user holds; replaces the actor id on the grants they issued, the credentials and models they created and the budgets they last edited with a fixed constant (`erased-subject`) that is not derived from the user; and removes them from every budget's extra recipients and every alert's delivered list. Usage rows depend on the erase mode: a hard delete removes them, an anonymizing erasure keeps the counters with the user replaced by a **random identifier per row** (so the rows cannot be linked to each other into a profile) and the credential reference removed. A row of a call still in flight is anonymized in both modes and removed later by retention. Credentials, models and budgets are organization assets and stay. A request with an empty subject id is refused before any query: it would otherwise match every row created without a user.
