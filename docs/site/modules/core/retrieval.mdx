# retrieval

Corpora and hybrid search over tenant data. Added to the always-loaded core by [ADR-0023](/adrs/core-retrieval-module) as the tenth core module: a module declares a **corpus** (a searchable collection of its own data) and the base indexes it and answers searches with a principal filter, over a vector engine behind a driver boundary. Inference is local by default: a corpus is `local_only` unless its owner declares `hosted_allowed`.

The module is always loaded, but its infrastructure is optional. It boots with no Qdrant configured and stays healthy in that state, in the same spirit as `llm` booting with zero credentials.

## Status

Delivery step 1 is in progress. This release ships:

- the SDK contract (`iface.Retrieval*`) and `module.ServiceRetrieval`;
- corpus registration and its validation;
- the engine contract and the Qdrant driver, with a conformance suite that any driver must pass;
- [indexing](#indexing): the transactional outbox, the index worker, chunking and the per-corpus state;
- [search](#searching-a-corpus): `iface.RetrievalSearch` and `iface.RetrievalPrincipalResolver` on the registered service, the search log and its retention.

It adds **no route, permission or navigation item**: search has no generic HTTP route, a module calls it in process. It adds five [settings](#configuration), three for indexing and two for search. Data-subject erasure (`DeleteBySubject`), the compliance wiring and the admin page arrive in the next releases; until then `DeleteBySubject` returns an error wrapping `errors.ErrUnsupported`.

## Degraded mode

`Init` never contacts Qdrant or an inference endpoint, and never returns an error: a core `Init` error is fatal, so missing infrastructure is a log line, never a failed boot.

| Situation | Behaviour in this release |
|---|---|
| `QDRANT_URL` unset | INFO log; no engine. Corpus registration works. Health reports the module healthy: not configured is the designed degraded mode |
| `QDRANT_URL` invalid | WARN log (the value is never logged); treated as not configured |
| `QDRANT_API_KEY` unset | WARN log; the URL is still used |
| Qdrant configured but unreachable | Registration still works. The module health check (`/v1/admin/modules/health`) reports the error `retrieval: the vector engine is unavailable`; `/ready` does not consult modules |
| Qdrant older than 1.20 | The driver refuses it in its health check |

Search answers `ErrRetrievalNotConfigured` when no engine is configured and `ErrRetrievalUnavailable` when it is configured but down. When a service search needs is missing at boot (authorization, membership, module status, or the `llm` inference companions), `Init` logs one warning naming them: without the first three every search fails closed, without the inference companions searches answer keyword-only and are marked degraded.

## Declaring a corpus

A module that owns searchable data registers a corpus in its `Init`, declares `retrieval` as a dependency so its `Init` runs after retrieval's, and resolves the registry from the service registry:

```go
func (m *Module) Dependencies() []string { return []string{"retrieval"} }

func (m *Module) Init(deps *module.Dependencies) error {
	registry, ok := module.GetTyped[iface.RetrievalCorpusRegistry](deps.Services, module.ServiceRetrieval)
	if !ok {
		return errors.New("notes: retrieval service not registered")
	}
	return registry.RegisterCorpus(iface.RetrievalCorpusSpec{
		Name:       "notes",
		Owner:      "notes",
		Permission: "notes.search.read",
		Filters: []iface.RetrievalFilterField{
			{Name: "status", Type: iface.RetrievalFieldKeyword, Description: "Workflow status"},
		},
		Ingestion: iface.RetrievalIngestionProfile{
			EmbedEndpoint: "embed-default",
			Chunking:      iface.RetrievalChunking{Strategy: "fixed", MaxTokens: 512, Overlap: 64},
		},
		Source: m.source, // implements iface.RetrievalSource: Load, Enumerate, Visible
	})
}
```

Registration is a local, syntax-only check. It never contacts the engine or `llm`; whether the embedding endpoint exists and satisfies the corpus locality is checked by the index worker (see [Health](#health)). The rules:

- The corpus name matches `^[a-z][a-z0-9_]{0,31}$` and is unique in the installation; the owner is a module name; the permission has the form `a.b[.c[.d]]` in lowercase; a `Source` is required.
- At most 32 filter fields. Names match `^[a-z][a-zA-Z0-9_]{0,63}$` and are unique; the type is one of the six listed under [Filters](#filters); the description is 1 to 500 bytes.
- `embedEndpoint` is required. The tokenizer is `word` (default) or `multilingual`; stemming needs a Snowball language and stop words a stop-word language. Chunking is `none` or `fixed` (`maxTokens` 1 to 4096, `overlap` below `maxTokens`). `hierarchical` chunking and enrichment are refused until delivery step 3.
- Locality `""` becomes `local_only`. Fusion defaults to dense weight 1, keyword weight 1 and 50 candidates per arm (weights in (0, 10], candidates 1 to 500). Rerank is off by default; its `topK` defaults to 20 (1 to 200), and enabling it needs an endpoint.
- The registry stores a normalized copy, so a later change to the caller's struct has no effect.

Registration closes when the retrieval module starts: every module's `Init` has run by then, so a module retried later cannot add a corpus. An invalid or duplicate declaration, or one made after that point, fails with `iface.ErrRetrievalInvalidSpec`.

## Filters

A search narrows its results with an `iface.RetrievalFilter` over the fields the corpus declared. The six field types and the values the engine stores:

| Type | Stored as |
|---|---|
| `keyword` | string |
| `keyword[]` | list of strings |
| `integer` | 64-bit integer |
| `float` | 64-bit float |
| `bool` | boolean |
| `datetime` | RFC 3339 in, stored as Unix milliseconds UTC |

A filter node is either a group (`and`, `or`, `not`) or a comparison of one field:

| Op | Meaning | Value |
|---|---|---|
| `eq` | Equals | `value` |
| `in` | Equals any of | `values` |
| `lt`, `lte`, `gt`, `gte` | Range | `value`, numbers and datetimes |
| `exists` | The field is present | none |

Not every op applies to every type:

| Type | Ops |
|---|---|
| `keyword`, `keyword[]` | `eq`, `in`, `exists` |
| `integer` | `eq`, `in`, `lt`, `lte`, `gt`, `gte`, `exists` |
| `float`, `datetime` | `lt`, `lte`, `gt`, `gte`, `exists` |
| `bool` | `eq`, `exists` |

Values must match the field type (datetimes as RFC 3339), strings are 1 to 1024 bytes, and `in` needs 1 to 100 values. `exists` takes no value; write absence as `not` around `exists`.

A filter is at most 4 levels deep, has at most 64 nodes and carries at most 100 values per `in`. Search validates a filter against the corpus's declared fields (a violation wraps `iface.ErrRetrievalInvalidFilter` and names the node path), then compiles it into the engine form, where a field is always addressed as a declared filter field. The search log keeps the filter as its JSON text, so a filter that has no JSON form (for example a `json.Number` the encoder rejects) is refused with `iface.ErrRetrievalInvalidFilter` too.

## Engine driver

The engine contract (`Engine`, `Point`, `Query`, `Selector`, `Filter`) is internal to the module and engine-neutral; consumers never import it. The Qdrant driver is a REST client over `net/http` and adds no dependency. Properties that matter to an operator:

- **Qdrant 1.20 or later.** The BM25 keyword arm uses the full-text index scoring introduced there. The driver's health check parses the server version, refuses an older one and lists collections to prove the API key works.
- **Tenant isolation is built into the query.** A query without a tenant or without principals is refused. The tenant and principal scope is repeated on every search arm and at the top level, and a result outside that scope is dropped and logged as a warning. BM25 statistics are scoped to the tenant, so one tenant's documents do not shift another's scores.
- **No secrets in errors or logs.** Driver errors are classified as unavailable or not found and never contain the Qdrant URL, the API key or a response body.
- **Conditional writes.** A point is overwritten only when the stored source revision is not newer than the incoming one, so a stale write never replaces a newer chunk in place. A stale writer can still add chunks (ordinals the newer revision does not have, or points recreated after a delete); they carry the old revision, are dropped on read, and are removed by the next cleanup of the item's other revisions (ADR-0023 D11).
- **Payload layout.** Runtime fields live under `_rt` (including the indexed text), declared filter fields under `f`. A user filter field is always rendered as `f.<name>`, so a caller cannot reach a runtime field.
- **Names.** Collections are named `<prefix>_<corpus>_g<generation>`; point ids are UUIDv5 over tenant, corpus, source id and ordinal.

## Indexing

Indexing is asynchronous and never blocks the owner's write. An owner declares a corpus (above), then records an **intent** in the same transaction as the write that changes the item:

```go
outbox, _ := module.GetTyped[iface.RetrievalOutbox](deps.Services, module.ServiceRetrieval)

// inside the transaction that saves the note
err := outbox.Enqueue(sessCtx, iface.RetrievalIntent{
	Corpus: "notes", SourceID: note.ID, Revision: note.Revision,
})
```

Pass the `mongo.SessionContext` of the transaction so the intent commits or aborts with the source write. A call carries at most 1000 intents; a `SourceID` is 1 to 256 bytes of valid UTF-8 without NUL; `Revision` is zero or more and must grow with every change of the item. The tenant in the context must be internal and the corpus registered. Keep `Revision` growing even when an item is deleted and later re-created with the same id: a re-created item with a lower revision is never indexed. Recording an intent for an item that is waiting after a failure does not shorten the wait, so an item fixed after an `invalid_item` failure is retried within 30 minutes. `Enqueue` needs only the database, not Qdrant: while the engine or the embedding endpoint is down, or the owning module is stopped, intents accumulate and are processed later.

The source must answer two calls:

- `Load(tenantID, ids)` returns the current item for each id, or `Deleted` for one that no longer exists. It answers only for the tenant passed, with at most one entry per id; an entry that is neither deleted nor carries an item, or whose item names another id, is treated as `invalid_item`. An item has a title (cut to 512 bytes, then prefixed to every chunk), text, declared filter fields, `VisibleTo` (up to 1000 entries) and `Subjects` (up to 100), each entry 1 to 256 bytes. An item that breaks these rules is retried every 30 minutes with the code `invalid_item`.
- `Enumerate(tenantID, cursor, limit)` pages through the tenant's items by an opaque cursor (empty to start, empty `Next` to end). The first time a corpus is indexed the worker walks it, 200 ids per page, to enqueue every existing item.

### What the worker does

The worker runs inside the base, one pass every `worker_poll_interval`. For each pass it checks every registered corpus (the embedding endpoint exists, is an embedding endpoint and respects the corpus locality), takes up to `worker_batch` due items round-robin across organizations, and for each item:

1. removes it from the index when it is deleted or covered by an erasure record;
2. loads it, validates it and splits the text into chunks;
3. if the indexed text is unchanged since the last run, only refreshes the stored filters and principals and skips the embedding;
4. otherwise embeds the chunks (32 per call, through the `llm` gateway and its budget), writes the points, and removes the points of older revisions.

A worker holds a short lease on each item and checks it before every write. A worker that stalls past its lease can still finish a write after another replica took the item over; it notices the lost lease at its next lease-checked step and marks the item for another pass, so the item is processed again before it counts as clean, and an item changed during indexing is likewise simply processed again. Stopping the module still releases or reschedules the item being processed, so it does not wait for its lease to expire (except when the stop lands on the lease check itself). A failure reschedules the item with a delay of 5 seconds doubling up to 30 minutes; items are never abandoned. Logs and the stored error carry only the corpus, tenant and item id and one of a closed set of codes (`source`, `source_behind`, `invalid_item`, `embed`, `budget`, `engine`, `deadline`, `tombstone`), never the text.

**Fairness.** Each pass resumes after the last organization the previous pass served, in organization ID order rather than by the age of their backlog, so a busy organization cannot starve the others: with more organizations waiting than `worker_batch`, every due organization gets a claim within `ceil(organizations / worker_batch)` passes. The initial build reads at most 16 pages per pass across all corpora and organizations and starts each pass where the previous one stopped. When an organization's `Enumerate` fails, the rest of that corpus is skipped for the pass (a wholly broken source costs one call per pass) and the next pass starts right after the failing organization, so one failing organization cannot block the others; a finished build costs nothing afterwards. Each replica keeps this position in memory.

### Chunking

- `none`: one chunk per item, cut at 64,512 bytes if longer.
- `fixed`: windows of `maxTokens` tokens, consecutive windows sharing `overlap` tokens, at most 512 chunks per item. `maxTokens` is 1 to 4096; registration refuses a larger value.

Tokens are counted approximately, without a model: a token is a run of non-whitespace characters of at most 32 characters (a longer run counts as consecutive 32-character pieces). One counted token is roughly one word, while the embedding model's own tokenizer produces roughly 1 to 2 tokens per word in English and Italian, so choose `maxTokens` at most half of the endpoint's maximum input; the endpoint's truncation covers any excess (the tail still reaches the keyword search, not the vector).

Each chunk records where it came from as `charStart` and `charEnd`, offsets in **characters** (Unicode code points) of the item text, not bytes.

### Changing the ingestion settings

The index is built for one *ingestion profile*: the embedding model, the analyzer, the chunking and the enrichment. Renaming the embedding endpoint does not change it (the model does); changing the model, the analyzer or the chunking does. When the declaration no longer matches the index, the corpus becomes `profile_changed`: the worker stops writing, intents keep accumulating and the existing index keeps serving. Rebuilding into a new generation arrives in delivery step 2; until then revert the declaration.

## Searching a corpus

A module that searches declares `retrieval` as a dependency, resolves the search interface once and calls it with the **caller's** context: the user and the internal organization in that context decide what comes back.

```go
func (m *Module) Init(deps *module.Dependencies) error {
	search, ok := module.GetTyped[iface.RetrievalSearch](deps.Services, module.ServiceRetrieval)
	if !ok {
		return errors.New("notes: retrieval service not registered")
	}
	m.search = search
	return nil
}

func (m *Module) find(ctx context.Context, text string) (*iface.RetrievalSearchResult, error) {
	res, err := m.search.Search(ctx, iface.RetrievalSearchRequest{
		Corpus: "notes",
		Query:  text,
		Filter: &iface.RetrievalFilter{Field: "status", Op: iface.RetrievalOpEq, Value: "published"},
		Limit:  10,
	})
	if errors.Is(err, iface.ErrRetrievalNotConfigured) {
		return nil, err // no vector engine on this installation
	}
	return res, err
}
```

**Never search inside a transaction.** Do not pass the `mongo.SessionContext` of a transaction (unlike `Enqueue`, which needs it): a successful search writes its search-log row with the context it was given, so that row would join your transaction, roll back with it, and leave a served result nobody can account for. Call `Search` before the transaction starts or after it commits, with the request context.

**Request bounds.** `Query` is 1 to 2000 characters and not blank. `Limit` is 1 to 100 (0 means 10). `Mode` is `hybrid` (the default), `dense` or `keyword`. `Fusion` optionally overrides the corpus's weights (each in (0, 10]) and candidates per arm (1 to 500) for this request. `Filter` follows [Filters](#filters). A request outside these bounds fails with `iface.ErrRetrievalInvalidRequest`.

**Who may search.** The organization in the context must be internal, the caller must hold the corpus's permission in it, and the corpus's owning module must be running. The caller's **principals** are resolved on every search: the user, the organization when the user is a member of it, the user's active roles in that organization, and whatever the registered principal contributors add (at most `principal_cap`). A result is returned only when one of its principals is among the item's `VisibleTo`. **Platform administrators get no bypass**: a `super_admin` resolves principals exactly like any other user and sees only what those principals allow.

**Before a result is returned**, every candidate is checked against the erasure records and against the owning module's `Visible` answer, at the indexed revision, within 2 seconds; a check that fails or times out fails the search with `iface.ErrRetrievalVisibilityCheck` rather than returning unchecked data.

**Results.** Each hit carries the source and chunk ids, its rank, a score (the reranker's when the corpus reranks, the fused score otherwise), a snippet of at most 300 characters around the query, its provenance (ordinal, page, character offsets) and the corpus locality.

**`degraded: true`** means the result may be below the corpus's usual quality or completeness, never that it contains anything the caller may not see:

- the dense arm could not run (inference down, the embedding endpoint changed model since the index was built, or it would send the text outside the corpus locality), so the search answered keyword-only;
- the reranker failed or would break locality, so the fused order stands;
- the checks dropped results and more permitted ones may exist;
- the corpus has no index yet (empty hits).

**Errors.** `ErrRetrievalForbidden` (external organization, no permission, no identity), `ErrRetrievalUnknownCorpus`, `ErrRetrievalInvalidRequest`, `ErrRetrievalInvalidFilter`, `ErrRetrievalCorpusUnavailable` (owner module stopped), `ErrRetrievalNotConfigured`, `ErrRetrievalUnavailable` (engine down, principals could not be resolved, the search log could not be written) and `ErrRetrievalVisibilityCheck`. Treat their text as internal: do not show it to end users.

**Every search is logged.** Each search that passes the access checks writes one row to `retrieval_search_log`: who searched, the query and the filter (as its JSON text, with datetimes in RFC 3339), the principals used, which sources came back and which people (subjects) they named, the outcome and timings. A result is returned only after its row is written; if the row cannot be written, the search fails with `ErrRetrievalUnavailable`. Searches refused at the access checks are not logged. Rows are deleted after `search_log_retention_days`. Query text, principals and subjects never go to the application logs.

`iface.RetrievalPrincipalResolver` (same registered service) returns the caller's principal set, for an owner that wants to check visibility the same way. It fails like search does: `ErrRetrievalForbidden` without an identity, `ErrRetrievalUnavailable` when the principals cannot be resolved (a contributor's own error text is never returned). `iface.RetrievalSearch.FilterSchema(corpus)` returns the corpus's declared filter fields.

## Configuration

The Qdrant settings are operator environment variables. The three worker settings (group Indexing) and the two search settings (group Search & audit) are module settings that can also be set from the environment; the worker settings are re-read on every pass, the search settings on every use.

| Env var | Default | Meaning |
|---|---|---|
| `QDRANT_URL` | unset | `http` or `https` URL of the Qdrant node (single node, internal network only, version 1.20 or later). Unset means retrieval runs without an engine |
| `QDRANT_API_KEY` | unset | API key sent to Qdrant. Always set one outside local development |
| `QDRANT_COLLECTION_PREFIX` | `orkestra` | Prefix of every collection name; `^[a-z][a-z0-9-]{0,31}$`. No underscore: corpus names may contain one, so prefix `a_b` with corpus `c` would share a collection with prefix `a` and corpus `b_c`. An invalid value logs a warning and the default is used |

| Setting (env var) | Default | Bounds | Meaning |
|---|---|---|---|
| `worker_lease` (`RETRIEVAL_WORKER_LEASE`) | `2m` | 30s to 15m | How long a worker owns one item while indexing it. Embedding and engine calls end a quarter of the lease before it expires |
| `worker_batch` (`RETRIEVAL_WORKER_BATCH`) | `32` | 1 to 256 | Items indexed per pass, shared round-robin across organizations. Zero or a negative value means the default 32 |
| `worker_poll_interval` (`RETRIEVAL_WORKER_POLL_INTERVAL`) | `5s` | 1s to 5m | Pause between passes |
| `principal_cap` (`RETRIEVAL_PRINCIPAL_CAP`) | `256` | 16 to 4096 | Maximum number of principals (user, organization, roles, contributors) a search may carry. A caller above it gets no results (`ErrRetrievalUnavailable`) until the cap is raised: it fails closed rather than dropping principals |
| `search_log_retention_days` (`RETRIEVAL_SEARCH_LOG_RETENTION_DAYS`) | `90` | 1 to 3650 | Search-log rows older than this are deleted daily (first run a minute after start, then every 24 hours). The log records who searched for what and which people the results named (ADR-0023 D12) |

Values outside the bounds are clamped to the nearest bound, except a `worker_batch`, `principal_cap` or `search_log_retention_days` of zero or less, which falls back to the default. The index is derived data: the owner's MongoDB collections stay the source of truth, so losing Qdrant loses no data and recovery is a rebuild. The collections are `retrieval_outbox`, `retrieval_tenant_progress` and `retrieval_search_log` (per organization), `retrieval_corpus_state` (one document per corpus for the installation) and `retrieval_erasures`.

## Health

The module health check (`/v1/admin/modules/health`) reports:

| Message | Meaning and action |
|---|---|
| (healthy) | No engine configured (designed degraded mode), or engine reachable and every corpus can be written |
| `retrieval: indexing disabled: <missing>` | Qdrant is configured but the worker could not start because a service it needs is absent (`LLMPinnedEmbedder`, `LLMInferenceProfiles`, `TenantIDLister`, `ModuleStatusReader`) or there is no database. With a database, intents still accumulate and are indexed once the worker runs; without one, `Enqueue` returns an error. Check that the `llm` and `tenant` modules are loaded |
| `retrieval: the vector engine is unavailable` | Qdrant did not answer its health check within 2 seconds. Check `QDRANT_URL`, the API key, the network and the Qdrant version (1.20 or later). Driver details are in the DEBUG log |
| `retrieval: corpus <c>: local_only corpus uses hosted endpoint "<e>"` | The corpus is `local_only` but its embedding endpoint is hosted. Point the corpus at an endpoint whose boundary is local, or have the owner declare `hosted_allowed` if sending the text to a hosted provider is acceptable |
| `retrieval: corpus <c>: embed endpoint "<e>" is not configured` | The endpoint name does not exist in `llm`. Create it or fix the declaration |
| `retrieval: corpus <c>: endpoint "<e>" is not an embedding endpoint` | The endpoint exists but is not an embedding endpoint. Use an embedding endpoint |
| `retrieval: corpus <c>: inference profile unavailable` | `llm` could not resolve the endpoint (or reports no dimensions). Check the endpoint's configuration and reachability |
| `retrieval: corpus <c>: vector engine unavailable` | Creating the corpus collection, or adding the payload index of a newly declared filter (done once per process the first time the corpus is indexed), failed. The corpus is skipped and retried on the next pass. Check Qdrant |
| `retrieval: corpus <c>: ingestion profile changed; indexing paused until a new generation is built` | The corpus declaration changed the model, analyzer or chunking. Revert the declaration; the build of a new generation is delivery step 2. Nothing is lost: intents are kept and the current index keeps serving |

Several problems are joined with `; `. A corpus whose owner module is stopped is skipped without a message; its intents wait.

The health check does not cover search: a service search needs that is missing at boot is reported once by the `Init` warning (see [Degraded mode](#degraded-mode)), and a failed search-log purge is logged as a warning and retried the next day.

## Legacy RAG contract

`iface.RAGQueryProvider`, `SourceRef`, `RAGQueryResponse` and `module.ServiceRAGQuery` predate the core-only base and nothing in it implements them; only archived addons used them. [ADR-0023](/adrs/core-retrieval-module) (D16) marks them deprecated in favour of `iface.RetrievalSearch` and removes them in a later release. A fork that still builds an archived `rag` addon should migrate to the retrieval contract before then.
